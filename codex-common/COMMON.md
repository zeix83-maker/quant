# Common development rules

- 진행 보고와 최종 설명은 간결한 한국어로 작성한다. 코드·명령·식별자는 원래 언어를 유지한다.
- 작업에 필요한 파일과 관련 문서부터 경로·심볼 검색으로 좁혀 읽는다. 프로젝트 전체, 생성물, 의존성, 로그를 무차별 읽지 않는다. 정확성에 필요하면 범위를 넓힌다.
- 같은 작업에서 확인한 사실과 결과를 재사용한다. 변경·실패·불확실성이 있을 때만 다시 분석하거나 검사한다.
- 기존 코드·도구·패턴을 우선 재사용한다. 요청 범위 밖 기능 추가, 불필요한 리팩터링, 의존성 추가를 피한다.
- 단순하고 되돌릴 수 있는 작업은 짧게 분석하고 바로 처리한다. 복잡하거나 위험한 작업은 충분히 추론하고 관련 경계 조건과 실패 경로를 검증한다.
- 변경에 맞는 필수 테스트와 프로젝트 검사를 수행한다. 통과 후에는 새 근거 없이 반복하지 않는다. 미실행·실패·접근 제한을 명확히 알리고 검증하지 않은 결과를 성공으로 보고하지 않는다.
- 로그·실행 결과는 결론, 핵심 오류, 필요한 위치 위주로 출력한다. 상세 로그가 필요하면 파일에 보존하고 비밀정보를 가린다.
- 보안, 개인정보 보호, 데이터 무결성, 필수 테스트를 토큰 절약보다 우선한다. 기존 사용자 설정과 정상 작업 흐름을 보존한다.
- 현재 작업에 필요한 도구와 스킬만 사용한다. 단순 작업을 불필요하게 분할하거나 위임하지 않는다.
- 프로젝트 고유 규칙·빌드·테스트 명령은 해당 프로젝트의 AGENTS.md와 하위 지침으로 관리한다. 기존 지침을 보존하고, 중복 공통 규칙을 프로젝트마다 복사하지 않는다. 사용자 요청과 적용되는 상위 지침을 따른다.
